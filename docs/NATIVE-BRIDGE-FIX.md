# 0.3.1 原生桥接修复与自动化测试

## 报错原因

后端把系统操作参数序列化为 JSON 数组，Windows 宿主使用 `JavaScriptSerializer.Deserialize<Dictionary<string,object>>` 解析后，数组的实际类型是 `System.Collections.ArrayList`。旧代码在调用本地操作前直接强制转换为 `object[]`，因此抛出 `InvalidCastException`。

影响范围包括项目选择、确认授权、诊断导出、备份选择、打开数据目录和弹出权限确认。此前桌面测试预先写入了已授权项目，未覆盖完整的项目选择和授权链路；此次已修正测试起点。

## 修复

- 新增 `native/HostArguments.cs`：以 `IList` 接收解析后的数组，统一复制成 `object[]`，兼容 `ArrayList` 和已有数组。
- 原生宿主统一通过该转换调用本地操作。
- 不合法的参数容器返回明确错误，不以强制类型转换异常退出。
- 界面统一清理已有的 `Error:` 前缀，避免出现 `Error: Error:`。
- 发布版本更新为 0.3.1，应用程序和压缩包均重新构建。

## 自动化测试分层

### 单元与原生回归

- 50 项 TypeScript / UI 单元测试通过。
- 9 项 .NET 原生解析回归测试通过，直接使用与软件一致的 JSON 解析器。
- 原生测试先复现旧代码的 ArrayList 转换异常，再核对空数组、中文多行确认参数、JSON 导出内容、已有数组、嵌套元素和非法容器。
- `npm test` 已包含原生回归测试，防止只跑前端和后端测试而漏测宿主。

### 打包后桌面自动化

测试使用独立数据库，不预置项目授权，从界面关联项目开始，实际经过浏览器、后台、原生宿主和 JSON 参数转换。

覆盖空队列、项目关联、三步创建任务、拒绝授权、接受授权、主题保存、诊断导出、备份创建与导入、最小化恢复和重启保留。系统对话框的选择由隔离测试文件提供，避免人工点击；测试文件只在显式测试模式生效，文件路径限制在隔离目录。此类检查不声称测试了 Windows 系统对话框的视觉布局。

真实 AGENT 桌面测试额外覆盖：点击执行时确认未授权项目、启动实际 AGENT、显示单次文件权限、创建文件、文件验收、显示结果和重启保留结果。测试会检查权限回调是否经过 `showApproval([])`，以及宿主是否报告错误，不再仅以「渲染器无异常」判断通过。
