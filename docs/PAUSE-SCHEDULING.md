# 0.3.2 暂停与继续

原先「暂停调度」只修改队列开关，当前 AGENT 不会停止。启动中的异步连接与环境检查还可能在暂停后重新开启调度。

现在「暂停调度」同时关闭队列和请求中断当前任务。已排队的其他任务保留在队列中，草稿与单独暂停的任务不会批量恢复。正在授权、连接、刷新执行环境或准备会话时，也能撤销本次启动；迟到的响应不能重新派发。

中断请求成功不代表执行已经停止。界面先显示「正在暂停」，保留执行锁并禁用继续，等 AGENT 的轮次终态和所有已开始的工具结束通知均收到，再显示「已暂停」。这些通知无论先后顺序都可以自动汇合。网络错误、停止失败或无法确认工具状态时，保留锁和错误说明，可点击「核对暂停状态」或在恢复检查中核对。暂停期间旧权限请求不能放行，旧轮次消息不能影响继续后的新轮次。

「继续执行」优先恢复本次全局暂停的任务。未修改任务版本时，使用 `thread/resume` 恢复原会话，再用 `turn/start` 开启新轮次，并明确要求先核对已有产物、只完成剩余工作。重新申明原项目目录、沙箱与逐次授权策略。若用户修改了暂停任务的配置，则创建新会话。暂停不是冻结进程，已发生的文件修改不会回滚，也不能保证任意外部操作都能精确从上一条指令续接。

回归覆盖：启动各阶段暂停、迟到的失败、定时刷新竞态、重复暂停、发送途中暂停、权限等待时暂停、工具晚到、多命令结束、停止失败、恢复原会话、暂停状态持久化，以及界面禁用和继续入口。

桌面测试使用独立数据目录和临时项目，实际启动 WebView2、点击执行、在文件授权等待时暂停、确认中断、点击继续、检查会话身份和最终文件。系统对话框答案由显式测试模式提供；原生桥接、AGENT、权限请求和文件操作均为真实链路。测试结果见 `pause-desktop-check.json`。

新版位于 `release-webview2/PawShift-0.3.2/`，根目录启动文件与 `npm start` 均指向新版。旧版正在运行时不会覆盖其运行文件；应退出旧版后启动新版，继续使用原用户数据目录。
